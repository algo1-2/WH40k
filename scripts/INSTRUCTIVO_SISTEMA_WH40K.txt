================================================================================
  1. QUÉ ES EL SISTEMA Y PARA QUÉ SIRVE
================================================================================

El sistema es un backend en Python (FastAPI) que actúa como "cerebro externo"
de una campaña de rol Warhammer 40K. El GPT de OpenAI consulta este backend
cada vez que necesita saber el estado actual de la campaña.

SIN este sistema:
  - El GPT inventa datos, mezcla personajes, pone a Alexander en QTN-3,
    dice que Tertius está inconsciente cuando está despierto, etc.

CON este sistema:
  - El GPT consulta GET /api/state y recibe JSON con el estado real
  - El GPT consulta GET /api/documents/{nombre} para leer fichas exactas
  - El GPT no puede alucinar porque tiene datos en tiempo real

================================================================================
  4. EL AUTOSYNC — CÓMO FUNCIONA EXACTAMENTE
================================================================================

ARCHIVO: scripts/wh40k_autosync.py en el repositorio

TRIGGER (cuándo corre):
  - Al iniciar sesión en Windows (LogonTrigger)
  - Cada 6 horas automáticamente (TimeTrigger, repetición PT6H)
  - Tiempo máximo de ejecución: 30 minutos (protección ante cuelgues)

PASO A PASO DE CADA EJECUCIÓN:

  Paso 1: Cargar caché de hashes
    Lee wh40k_file_hashes.json para saber los hashes SHA-256 de la
    última ejecución. Si un archivo no cambió, lo omite.

  Paso 2: Buscar archivos fuente (orden de prioridad)
    PRIORIDAD 1: C:\Users\UsuarioCompuElite\Desktop\WH40K\
      Busca los 6 archivos .docx directamente en tu escritorio.
    PRIORIDAD 2: C:\...\wh40k_engine\ (carpeta watcher)
      Si hay un .zip en esa carpeta, lo abre, extrae los .docx y los usa.

  Paso 3: Comparar hashes
    Calcula SHA-256 para cada .docx encontrado.
    Si hash == hash en caché Y el .txt ya existe: OMITE el archivo.
    Si hash cambió O el .txt no existe: PROCESA el archivo.

  Paso 4: Convertir .docx a .txt
    Abre el .docx como ZIP (los .docx son ZIPs internamente).
    Lee word/document.xml con xml.etree.ElementTree.
    Extrae párrafos del namespace WordprocessingML.
    Une los párrafos con salto de línea.
    Guarda como UTF-8 puro.

  Paso 5: Escribir en el repositorio
    Guarda NOMBRE_SIN_ESPACIOS.txt en data/alexander/
    Guarda también el .docx original en data/alexander/

  Paso 6: Git add + commit
    git add -A (incluye todos los cambios)
    git commit -m "AutoSync FECHA: lista de archivos cambiados"
    Si no hay nada que commitear, termina aquí.

  Paso 7: Leer token de GitHub
    Lee el token OAuth desde Windows Credential Manager usando
    Advapi32.dll/CredReadW.
    Target: "GitHub - https://api.github.com/algo1-2"
    Sin este token, el push falla.

  Paso 8: Push a ambos repositorios
    git push --force .../WH40K-API.git main:main
    git push --force .../WH40k.git main:main
    El --force evita rechazos por divergencia de historial.

  Paso 9: Guardar caché de hashes actualizado
    Guarda wh40k_file_hashes.json con los nuevos hashes.

  Paso 10: Log
    Registra todo en wh40k_autosync.log con timestamp.

================================================================================
  5. VERCEL — CÓMO FUNCIONA EL SERVIDOR EN PRODUCCIÓN
================================================================================

Vercel aloja la API. Cuando detecta un push en GitHub, lanza deployment.

CONFIGURACIÓN CRÍTICA (vercel.json — NO MODIFICAR):
  {
    "version": 2,
    "builds": [{"src": "api/index.py", "use": "@vercel/python"}],
    "routes": [{"src": "/(.*)", "dest": "api/index.py"}]
  }

  NOTA: La configuración usa "routes" (no "rewrites").
  NOTA: El destino es "api/index.py" (no "/api" ni "api/").
  Si se cambia esto, el deployment falla o devuelve 404 en todo.

PROCESO DE DEPLOYMENT EN VERCEL:
  1. Vercel recibe el webhook de GitHub (push detectado)
  2. Clona el repositorio en Amazon Linux 2
  3. Lee vercel.json -> sabe qué construir
  4. Lee runtime.txt -> instala Python 3.11
  5. Instala dependencias de requirements.txt
  6. Empaqueta api/index.py como función serverless
  7. Activa el deployment -> reemplaza el anterior en producción
  8. La memoria del proceso es EFÍMERA (sin estado persistente en RAM)

ESTADO PERSISTENTE:
  campaign_state.json vive en el repositorio de GitHub.
  Los cambios vía POST /api/state/delta se escriben en disco del servidor,
  pero NO persisten entre deployments (Vercel es serverless).
  Para persistir cambios de estado: ejecutar el autosync manualmente.

RUTAS DE LA API EN PRODUCCIÓN:
  GET  /api/state
  POST /api/action
  POST /api/state/delta
  GET  /api/documents/{filename}
  GET  /api/domain/status
  POST /api/state/checkpoint
  (ver api/openapi.json para lista completa)

AUTENTICACIÓN:
  Todas las rutas requieren header: x-api-key: wh40k_secret_key_12345
  Sin este header, la API devuelve 403.

REGLA ABSOLUTA DE FILENAMES EN GIT:
  El servidor Linux de Vercel NO acepta filenames con espacios en el repo.
  Causa crashes silenciosos durante el packaging del deployment.
  TODOS los archivos en el repo deben usar guiones bajos, nunca espacios.
    CORRECTO:   BASES_Y_DOMINIOS.txt
    INCORRECTO: BASES Y DOMINIOS.txt

================================================================================

FALLO 1: El GPT narra con datos incorrectos (QTN-3, Tertius inconsciente, etc.)
---------------------------------------------------------------------------------

DIAGNÓSTICO:
  Ejecutar en PowerShell:
    Invoke-RestMethod -Uri "https://wh-40k.vercel.app/api/state" `
      -Headers @{"x-api-key"="wh40k_secret_key_12345"}

  Si location dice "Refugio QTN-3" -> problema en Vercel (ver Fallo 2).
  Si location dice "Medicae Station Rho-9" -> problema en el GPT (ver abajo).

SOLUCIÓN A (Vercel sirve estado viejo):
  Ejecutar autosync manualmente:
    python "C:\Users\UsuarioCompuElite\Documents\GitHub\WH40K-API\scripts\wh40k_autosync.py"
  Esto force-pushea el estado correcto y dispara redeploy.

SOLUCIÓN B (API bien, GPT alucina igual):
  Abrir configuración del GPT en ChatGPT -> "Edit GPT"
  Verificar que el system prompt incluya la instrucción de consultar /api/state.
  Verificar que openapi.json apunte a https://wh-40k.vercel.app.

FALLO 2: Vercel deployment falla (Build Error o Function Error)
---------------------------------------------------------------

CAUSAS POSIBLES (en orden de probabilidad):

  A) Archivos con espacios en el nombre subidos al repositorio
     DIAGNÓSTICO (PowerShell desde el repo):
       & "C:\...\git.exe" -C "C:\...\WH40K-API" ls-files | Where-Object { $_ -match " " }
     Si devuelve archivos: esos son el problema.
     SOLUCIÓN: Ejecutar el autosync. Siempre escribe archivos sin espacios.

  B) vercel.json fue modificado incorrectamente
     DIAGNÓSTICO: Ver el contenido actual de vercel.json
     SOLUCIÓN: Restaurar manualmente:
       {
         "version": 2,
         "builds": [{"src": "api/index.py", "use": "@vercel/python"}],
         "routes": [{"src": "/(.*)", "dest": "api/index.py"}]
       }

  C) requirements.txt tiene error de versión o dependencia inexistente
     DIAGNÓSTICO: Ver logs de build en Vercel Dashboard
     SOLUCIÓN: El requirements.txt correcto es:
       fastapi>=0.100.0
       uvicorn>=0.20.0
       pydantic>=2.0.0

  D) Error de importación en engine/main.py
     DIAGNÓSTICO: Los logs de Vercel muestran el traceback exacto
     SOLUCIÓN: Revisar el import que falla y corregir la ruta o el módulo

  E) runtime.txt no existe o tiene formato incorrecto
     DIAGNÓSTICO: Verificar que runtime.txt dice exactamente: python-3.11
     SOLUCIÓN: Crear/corregir el archivo con ese contenido exacto

FALLO 3: El AutoSync no corre automáticamente
----------------------------------------------

DIAGNÓSTICO:
  1. Verificar que la tarea existe:
       schtasks /Query /TN "WH40K_AutoSync"
  2. Ver el log:
       Get-Content "C:\...\.gemini\antigravity\scratch\wh40k_autosync.log" -Tail 50

CAUSAS Y SOLUCIONES:

  A) La tarea no está instalada
     SOLUCIÓN: Ejecutar como administrador:
       python "C:\...\scripts\install_autosync_task.py"

  B) La tarea existe pero falla silenciosamente
     SOLUCIÓN: Correr manualmente para ver el error:
       python "C:\...\scripts\wh40k_autosync.py"

  C) El token de GitHub venció o fue revocado
     SÍNTOMA EN LOG: "No se pudo leer token" o "authentication failed"
     SOLUCIÓN:
       1. Abrir GitHub Desktop -> File -> Options -> Accounts
       2. Sign out -> Sign in again (renueva el token en Credential Manager)
       3. El autosync lo toma automáticamente en la próxima ejecución

  D) Python no está en el PATH del Task Scheduler
     SÍNTOMA: Log vacío, tarea dice "Last Run Result: 0x1"
     SOLUCIÓN:
       1. En PowerShell: where.exe python
          Copia la ruta exacta que devuelve (ej: C:\Program Files\Python311\python.exe)
       2. Editar install_autosync_task.py -> cambiar la variable PYTHON por esa ruta
       3. Reinstalar la tarea: python install_autosync_task.py

  E) Los archivos .docx no están en Desktop/WH40K/
     SÍNTOMA EN LOG: "No se encontraron archivos .docx fuente. Abortando."
     SOLUCIÓN: Verificar que los 6 .docx están en Desktop/WH40K/

FALLO 4: La API devuelve 404 en todas las rutas
------------------------------------------------

CAUSAS:

  A) Deployment de Vercel caído o en error
     SOLUCIÓN: Ir a https://vercel.com/wh-40k/wh-40k -> ver estado
     Si está en "Building": esperar 2-3 minutos
     Si está en "Error": ver los logs y corregir el error señalado

  B) vercel.json tiene destination incorrecto
     SOLUCIÓN: Restaurar vercel.json correcto (ver sección 5)

  C) El proyecto en Vercel está desconectado del repositorio
     SÍNTOMA: No hay deployments recientes aunque se hicieran pushes
     SOLUCIÓN:
       1. Ir a https://vercel.com/wh-40k/wh-40k/settings
       2. Ver "Git Repository" -> verificar que apunta a algo1-2/WH40K-API
       3. Si está desconectado -> reconnectar manualmente en el dashboard

FALLO 5: El estado se resetea o pierde datos entre sesiones
------------------------------------------------------------

CAUSA: Vercel es serverless. Un nuevo deployment borra el estado en RAM.
El estado persistente es campaign_state.json en el repositorio de GitHub.
Si el autosync no lo actualizó antes del deployment, vuelve al estado previo.

SOLUCIÓN PREVENTIVA:
  Después de una sesión con cambios importantes, ejecutar:
    python "C:\...\scripts\wh40k_autosync.py"

SOLUCIÓN DE EMERGENCIA (si se perdió el estado):
  1. Abrir C:\...\WH40K-API\campaigns\alexander\campaign_state.json
  2. Corregir manualmente: location, characters, pacts_and_debts, state_revision
  3. Ejecutar autosync para pushear la corrección a GitHub

FALLO 6: git push falla con "rejected non-fast-forward"
--------------------------------------------------------

SÍNTOMA EN LOG: "rejected main -> main (non-fast-forward)"
CAUSA: El repositorio remoto tiene commits que el local no tiene.

SOLUCIÓN (PowerShell desde C:\...\WH40K-API):
  $git = "C:\...\git.exe"
  & $git -C "." fetch origin
  & $git -C "." push origin main --force

FALLO 7: AutoSync no detecta cambios en el .docx
-------------------------------------------------

CAUSA: El hash SHA-256 en caché coincide con el archivo actual
(el docx se abrió y cerró sin modificar su contenido binario real).

SOLUCIÓN: Borrar el caché de hashes para forzar resincronización total:
  Remove-Item "C:\...\.gemini\antigravity\scratch\wh40k_file_hashes.json" -Force
  python "C:\...\scripts\wh40k_autosync.py"
